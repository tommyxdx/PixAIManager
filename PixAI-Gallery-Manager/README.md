# PixAI 图库管理（PixAI Gallery Manager）

一个 Chrome 扩展，在 pixai.art 页面里批量管理**你自己生成的图片**：浏览全部生成记录、建本机收藏夹分类、按规则命名批量下载原图、在 PixAI 上加星或取消星标、批量永久删除。

它只做管理，**不会生成图片**，也不会调用任何生成接口。

## 功能

- **全部生成 / PixAI 星标**：分页读取你的生成记录（关键词、日期、类型筛选在 PixAI 服务器上执行），支持“加载全部”。
- **我的收藏夹（仅本机）**：自己建任意多个收藏夹，把图片加进去分类；可整夹下载、重命名、删除；可导出 / 导入 JSON。
- **PixAI 作品收藏夹**：只读显示你在 PixAI 上的作品收藏夹，可整夹下载。
- **批量下载原图**：按模板命名；WebP 图片默认转成 PNG（和 PixAI 生成页的下载按钮一样，见下文），也可以保留原始 WebP；视频是 MP4；默认打包成一个 ZIP，里面附带下载报告，失败的可以一键重试（见下文）。也可以在设置里改成单独的文件。
- **加星 / 取消星标**：和 PixAI 网页版 Library 里的星标是同一个，网页版 `?fav=1` 里也能看到。
- **批量删除**：永久删除，需要确认（见下文）。
- 预览大图、复制提示词。
- **中英文界面**：右上角的“EN / 中文”按钮随时切换；设置里还可以选“自动（跟随浏览器）”。扩展名称和商店介绍也有中英文两份。

## 安装

1. 打开 Chrome（116 或更新版本），地址栏输入 `chrome://extensions` 回车。
2. 打开右上角的 **开发者模式**。
3. 点 **加载已解压的扩展程序**，选择 `PixAI-Gallery-Manager` 这个文件夹（里面有 `manifest.json` 的那一层）。
4. 打开 https://pixai.art 并登录。页面左下角会出现“图库管理”按钮；也可以点浏览器工具栏上的扩展图标。不在 pixai.art 页面时点图标，会新开一个 PixAI Library 页面并自动打开界面。

更新代码后，在 `chrome://extensions` 里点扩展卡片上的刷新按钮，再刷新 pixai.art 页面。没刷新的旧页面里点“图库管理”会提示你先刷新。

## 文件命名规则

默认模板是 `{folder}_{time}_{prompt}`，默认子目录是 `PixAI/{folder}`，都可以在“设置”里改。

| 变量 | 含义 |
|---|---|
| `{folder}` | 收藏夹名。在“全部生成”或“星标”里下载时为空 |
| `{time}` | 图片的**生成时间**（本地时间），格式 `YYYYMMDD-HHmmss` |
| `{prompt}` | 提示词的前几个标签（默认 3 个，可设 2 到 5 个），用 `_` 连接 |
| `{index}` | 这张图在同一次生成里的序号（从 1 开始） |
| `{task}` | 生成任务 ID |
| `{media}` | 图片 ID |

处理规则：

- 提示词标签：去掉 `<lora:...>` 之类的尖括号块、`@image1`、`BREAK`、`score_9` 这类分数标签和权重写法（`(smile:1.2)` 变成 `smile`），按逗号、中文逗号、顿号、分号、换行切开。
- 默认跳过质量词：masterpiece、best quality、highres、absurdres、very aesthetic、8k 等（设置里可关闭）。
- 如果提示词是一整句自然语言（只有一段且超过 4 个词），取前几个**词**。
- 标签里的空格和下划线换成 `-`，每个标签最多 24 个字符。
- 某个变量为空时，它和旁边的下划线一起省略。
- 同一次生成有多张图时，自动在末尾加 `_序号`（模板里已经有 `{index}` 时不加）。
- 文件名最长 120 个字符，超长时先减少提示词标签。
- Windows 和 Chrome 下载不允许的字符（`<>:"/\|?*~`、控制字符和不可见的格式字符）换成 `-`；`CON`、`NUL`、`COM1` 这类保留名前面加 `_`；中文等 Unicode 字符保留。
- 不在收藏夹里下载时，子目录里的 `{folder}` 用“生成记录”代替（英文界面下是 `Generations`；设置里可改成固定的名字）。
- 同名文件不会覆盖，Chrome 会自动加 `(1)`、`(2)`。

例子（生成时间为 2026-11-03 14:05:09）：

| 情况 | 提示词 | 保存路径（相对于下载文件夹） |
|---|---|---|
| 收藏夹“风景”里下载 | `masterpiece, best quality, 1girl, silver hair, (smile:1.2), <lora:abc:0.7>` | `PixAI/风景/风景_20261103-140509_1girl_silver-hair_smile.png` |
| 全部生成里下载，4 张中的第 2 张 | 同上 | `PixAI/生成记录/20261103-140509_1girl_silver-hair_smile_2.png` |
| 自然语言提示词 | `A girl holding flowers in a sunny garden` | `PixAI/生成记录/20261103-140509_A_girl_holding.png` |
| 中文标签 | `女孩，银发、微笑，樱花` | `PixAI/生成记录/20261103-140509_女孩_银发_微笑.png` |
| 只有质量词 | `masterpiece, best quality, highres` | `PixAI/生成记录/20261103-140509.png` |

PixAI 作品收藏夹里的作品，扩展会先查询它原来的生成任务，用**生成时间**命名；查不到（例如上传的作品）时用作品的发布时间。

## 打包下载（ZIP）

一次下载多张图时，默认把它们打包成一个 ZIP，方便核对哪些下载成功了：

- 保存位置和散装文件一样，例如 `下载文件夹/PixAI/风景/PixAI_风景_20261103-140509.zip`（名字里是收藏夹名和开始下载的时间）。
- ZIP 里的图片按上面的规则命名，文件的修改时间是图片的生成时间。同名的图片自动加 ` (1)`、` (2)`。
- 每个 ZIP 里都有一份 `_下载报告.txt`（英文界面下是 `_download-report.txt`）：写明成功几个、失败几个，失败的每个文件都列出文件名、原因（例如“请求失败（HTTP 404）”“网络超时”）和原图链接，后面是成功的文件列表。
- 单张图片下载失败时会自动重试 2 次（网络错误、超时、429 和 5xx；403 和 404 不重试）。
- 下载完成后，右下角任务卡片上有 **重试失败项**（只重新下载失败的那些，生成一个新的 ZIP）、**复制失败列表** 和 **打开所在文件夹**。
- 文件很多时自动分成多个 ZIP：`…_part1.zip`、`…_part2.zip`……每个最大 1000 MB（设置里可选 500 / 1000 / 2000 MB），每个 ZIP 都有自己的报告，最后一个报告里有整个任务的总数。
- 中途点“取消”：已经下载好的图片仍然会存成 ZIP，报告里注明任务已取消；没下载的不会再下载。
- ZIP 不压缩（图片本身已经是压缩格式），Windows 资源管理器、7-Zip、macOS 都能直接打开，中文文件名正常显示。
- 只下载一张图时总是直接保存图片，不打包。
- 打包在扩展内部完成（Chrome 的“离屏文档”），图片不会经过任何其他服务器。

想要以前那样一张一张的文件，在“设置 → 下载方式”里选“单独的文件”。

## WebP 和 PNG

PixAI 的生成图大多以**无损 WebP** 格式存储。PixAI 网页上不同的下载按钮处理方式不一样：

- 生成页图片下方的下载按钮、“全部下载”、作品分享里的下载：把 WebP 在浏览器里画到画布上，再存成 PNG。
- 大图查看器里的下载、Library 多选打包下载：直接保存原始 WebP。

扩展默认和生成页的下载按钮一样，把静态 WebP 转成 PNG（“设置 → 把 WebP 图片转成 PNG 保存”）：

- 转换方法和 PixAI 网页版相同，得到的 PNG 与网页版下载的**逐字节一致**；和原始 WebP 相比画面完全相同（用真实图片和独立的解码器核对过）。
- PNG 文件大约是 WebP 的 2 倍大。
- 动图（动态 WebP）不转换；视频保持 MP4；原本就是 PNG / JPG 的图片不变。
- 关闭这个选项，就保存 PixAI 上的原始 WebP 文件（更小，画面一样）。
- 打包下载时，报告里会写明有几个 WebP 转成了 PNG。
- 下载图片时遇到网络错误、超时、429 或 5xx 会自动重试 2 次；仍然失败（或 403、404）的图片列为失败，可以“重试失败项”，不会悄悄存成 WebP。

## 本机收藏夹只存在这个浏览器里

“我的收藏夹”保存在 Chrome 扩展自己的本地存储（`chrome.storage.local`）里：

- 不会上传到 PixAI，不会同步到其他电脑或其他 Chrome 用户资料。
- 卸载扩展、或在扩展设置里清除数据，收藏夹就没了。
- 收藏夹里存的是图片链接、提示词、生成时间等信息，不是图片文件本身。
- 用“导出”保存成 JSON 文件备份，在别的电脑上用“导入”恢复。导入按收藏夹名合并，同一张图不会重复加入；文件里不合法的条目或不属于 PixAI 图片域名的链接会被跳过。导出文件不含任何登录信息。

## 为什么生成的图片不能放进 PixAI 收藏夹

PixAI 的收藏夹（Collection）只能收录**已发布的作品**、模型和配方，不能收录生成记录里的图片。PixAI 网页版本身也没有“把生成图片加入收藏夹”的功能，生成图片只有一个星标。

要把一张生成图放进 PixAI 收藏夹，只能先把它发布成作品。这会创建作品、要经过审核，设成私密后不能再改回公开，而且已发布的图片无法再用批量删除删掉。所以这个扩展**不替你发布**，而是用本机收藏夹来分类，PixAI 作品收藏夹只读显示、可下载。

## 删除是永久的

- PixAI 没有回收站，删除后**无法恢复**，已用积分不会退还。
- 删除前会弹出确认框，写明张数、涉及几个生成任务、几张已发布会被跳过；必须勾选“我明白删除后无法恢复”才能点删除。
- 已发布为作品的图片会被 PixAI 跳过，不会删除。已发布的视频任务扩展也会跳过。
- 视频是按整个生成任务删除的。删除前扩展会先向 PixAI 查询这个任务，确认它确实是这个视频、已完成且未发布，否则不删。
- 删除成功的图片也会从本机收藏夹里移除。
- PixAI 作品收藏夹里的作品不能在这里删除。

## 请求节奏

扩展模仿网页版的请求方式，尽量不给 PixAI 增加负担：

- 每个任务同一时间只发一个 API 请求。
- 删除和加星每次最多 50 张；查询图片信息每次最多 100 个 ID。
- “加载全部”翻页时每页之间间隔 250 毫秒；查作品生成时间时每个请求之间也间隔 250 毫秒。
- 同时最多下载 3 个文件（所有下载任务合计，打包下载也算在内）。
- 读取请求遇到 429 或 5xx 时自动等待后重试（1 秒起翻倍，最多 30 秒，最多 4 次）；删除和加星失败时**不会自动重试**。

## 权限和隐私

- 只申请 `downloads`（保存文件）、`storage` 和 `unlimitedStorage`（保存收藏夹和设置）、`offscreen`（在扩展内部打包 ZIP）。没有访问其他网站的权限，不读取浏览记录、Cookie 或标签页。
- 不向开发者或任何第三方发送数据，没有统计分析和广告。隐私政策全文见 `store/PRIVACY.md`。
- 扩展只在 `https://pixai.art/*` 页面上运行。
- 登录令牌每次请求时从 pixai.art 页面的 localStorage 读取，只发送给 `api.pixai.art`，不保存、不记录、不传给扩展后台，也不发往任何其他地方。
- 只显示和下载 `images-ng.pixai.art`、`cdn.pixai.art`、`api.pixai.art` 上的图片；提示词等文字只作为纯文本显示。

## 关于服务条款

- 这个扩展使用的是 pixai.art 网页版自己调用的接口（`api.pixai.art`），请求从你已登录的浏览器发出，用的是你自己的登录状态，效果等同于你在网页上手动操作。
- 它只用于管理（列出、下载、加星、删除），不生成图片，不调用生成相关的接口。
- 这是**非官方**扩展，与 PixAI 没有关联，也没有得到 PixAI 的认可。
- PixAI 可能随时修改这些接口，届时扩展可能部分或全部失效。
- 是否符合 PixAI 的服务条款，请你自行判断。

## 本地测试（开发者）

不需要登录 PixAI，也不会访问 PixAI 服务器：

```bash
# 1. 启动模拟 PixAI 接口（只用 Python 标准库）
python tests/mock_server.py 18765

# 2. 在扩展根目录启动静态服务器
python -m http.server 8000

# 3. 浏览器打开
#    http://127.0.0.1:8000/tests/unit.html      纯函数测试，页面顶部显示 PASS / FAIL 数
#    http://127.0.0.1:8000/tests/harness.html   完整界面，连接模拟接口，下载只记录不保存
#    http://127.0.0.1:8000/tests/bg_harness.html 真实的 background.js 和离屏文档脚本（chrome.* 用桩代替）
```

`harness.html?zipPartKB=16` 会把 ZIP 分得很小，用来测试分卷。两个测试页“保存”的 ZIP 会上传到模拟服务器，存在 `PGM_MOCK_UPLOAD_DIR` 环境变量指定的文件夹（默认是系统临时文件夹下的 `pgm-mock-uploads`），可以用 Python 的 `zipfile` 或直接解压检查。

模拟服务器有 40 个生成任务（分 3 页，含 4 张图的任务、一个视频、两个已发布、部分加星）和两个作品收藏夹。`harness.html?loggedOut=1` 可测试未登录状态；页面上还有模拟 503、重置数据、查看请求日志（会标出不在允许列表里的请求）等按钮。

## 打包上架

```bash
python tools/package.py
```

生成 `dist/PixAI-Gallery-Manager-<版本>.zip`，只包含扩展运行需要的文件，并检查清单里引用的文件和多语言文字是否齐全。上架步骤、后台各项怎么填、权限说明见 `store/DASHBOARD.md`；商店介绍文案见 `store/LISTING.md`。
